# Требования к системе

## Функциональные требования

### 1. Доменная модель и сервисы
- Поддержка основных сущностей: Project, Dataset, Methodology, CalculationResult, Scenario, ValidationIssue/Result, DataQualityReport
- Реестр методик с возможностью регистрации новых методик
- Сервис сценариев для управления вычислениями
- Сервис расчётов для выполнения гидростатистических методов
- Сервис контроля качества данных

### 2. GUI-приложение
- Главное окно с навигацией по разделам (минимум 19 разделов)
- Вкладка "Проект" для создания/открытия/сохранения проектов в формате .hsp
- Вкладка "Методики" для просмотра и запуска методик
- Диалог "Качество данных" для оценки входных данных
- Фоновые рабочие процессы для длительных вычислений
- Таблицы отображения датасетов и параметров
- Поддержка tolerant-разбора файлов проектов

### 3. Методики расчёта (P0)
- stats_parameters: статистические параметры ряда (СП 33-101-2003)
- frequency_pearson3: кривая обеспеченности (распределение Пирсона III) (СП 33-101-2003)
- frequency_kritsky_menkel: кривая обеспеченности (метод Крицкого-Менкеля) (СП 33-101-2003)
- homogeneity_full: проверка однородности (12 критериев) (СП 33-101-2003, Прил. А)
- trends_full: анализ тренда (линейный, Манн-Кендалл, Сен, Pettitt) (СП 33-101-2003, разд. 5.6)
- max_runoff: максимальный сток (паводки) (СП 33-101-2003, разд. 8)
- min_runoff: минимальный сток (30-суточные зимние минимумы) (СП 33-101-2003, разд. 9)
- flow_duration: кривая длительностей (СП 32.13330.2018)
- reservoir_regulation: многолетнее регулирование стока (СП 58.13330.2019)

### 4. Консольные инструменты
- Инструмент запуска методик из командной строки (tools/run_methodology.py)
- Возможность запуска с демонстрационными данными
- Возможность указания собственного файла данных
- Вывод результатов в консоль и сохранение в проект

### 5. Тестирование
- Автоматические unit-тесты для доменной логики и сервисов
- Минимальное покрытие тестами критических путей
- Тесты эквивалентности для проверки корректности реализации методик
- Тесты персистентности форматов файлов

## Нефункциональные требования

### 1. Производительность
- Время выполнения расчётов для типичных наборов данных должно быть приемлемым для интерактивного использования
- Фоновые задачи не должны блокировать GUI-интерфейс
- Необходимо избегать задержек при переключении между вкладками

### 2. Надёжность
- Корректная обработка ошибочных входных данных
- Информативные сообщения об ошибках для пользователя
- Сохранение состояния проекта при аварийном завершении
- Валидация применимости методик перед запуском расчётов

### 3. Удобство использования
- Интуитивно понятный интерфейс с логической группировкой функциональности
- Согласованные паттерны взаимодействия во всех разделах приложения
- Подсказки и документация внутри приложения
- Поддержка стандартных клавиатурных сочетаний

### 4. Сопровождаемость
- Чёткое разделение ответственности между слоями (домен, сервисы, GUI)
- Соблюдение единого стиля кодирования
- Наличие автоматических тестов для регрессионного контроля
- Документирование публичных API и сервисов

### 5. Совместимость
- Поддержка Python 3.10+
- Работа на Windows (основная платформа разработки)
- Возможность запуска в изолированном окружении (venv, conda)
- Совместимость с указанными версиями зависимостей

### 6. Безопасность
- Базовая валидация входных файлов перед обработкой
- Ограничение на выполнение произвольного кода из файлов проектов
- Безопасная обработка Excel-файлов (openpyxl)

### 7. Установка и деплой
- Простой процесс установки зависимостей через pip
- Возможность создания автономного исполняемого файла через PyInstaller
- Документированный процесс сборки и распространения

## Ограничения и предположения

1. Основная целевая аудитория - русскоязычные инженеры-гидрологи
2. Приоритет отдаётся точности расчётов согласно нормативным документам
3. GUI-приложение ориентировано на десктопное использование
4. Предполагается работа с табличными данными в форматах Excel и CSV
5. Расчёты выполняются на центральном процессоре без использования GPU
6. Текущая реализация не предполагает распределённых вычислений
7. Формат файла проекта .hsp основан на JSON и обратностени совместим
8. Методы расчёта реализованы как независимые обработчики с чётким интерфейсом
